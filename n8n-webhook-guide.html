Sektion 1

Problemet forklaret

Når n8n kører som HA Add-on og eksponeres via Cloudflare Tunnel med Access-beskyttelse, opstår der tre sammenfaldende problemer:

Problem 1 — Cloudflare Access blokerer webhooks

Cloudflare Access beskytter hele domænet. Når en ekstern tjeneste forsøger at ramme en webhook-URL, mødes den af en login-skærm i stedet for n8n.

Problem 2 — HA Ingress forvrænger URL'er

n8n Add-on'et kører bag Home Assistant's Ingress-system. Ingress tilføjer en dynamisk token-sti til alle URL'er:

https://n8n.ditdomæne.com/api/hassio_ingress/[TOKEN]/webhook-test/[uuid]

Denne URL er ubrugelig for eksterne systemer — tokenet skifter og stien går igennem Access.

Problem 3 — WEBHOOK_URL overrides ikke editor-visningen

Selvom man sætter WEBHOOK_URL korrekt, viser n8n's editor stadig Ingress-URL'en, fordi add-on'et tvinger N8N_EDITOR_BASE_URL til Ingress-stien. Dette er en arkitekturel begrænsning ved at køre n8n som HA Add-on.

⚠️ Bypass-regler i Cloudflare Access (én applikation med multiple politikker) løser ikke problemet, fordi URL'en stadig indeholder Ingress-tokenet og peger på det beskyttede domæne.
Sektion 2

Løsningens arkitektur

Løsningen er at splitte UI og webhooks på to separate subdomæner. Derved kan Access beskytte dashboardet, mens webhooks aldrig rammer Access.

Ekstern tjeneste ──────────────────────────────────────────────────────┐ │ https://n8n-hooks.ditdomæne.com/webhook/[uuid] │ │ │ ├── Cloudflare Tunnel │ │ └── Ingen Access-applikation knyttet │ │ └── n8n container:5678 (direkte) │ │ └── ✓ Webhook modtages │ │ │ Browser (dig) ───────────────────────────────────────────────────────────┘ │ https://n8n.ditdomæne.com │ ├── Cloudflare Access [email login] │ └── Cloudflare Tunnel │ └── homeassistant:8123 (HA Ingress) │ └── n8n editor UI (WebSockets virker)
Subdomæne Peger på Cloudflare Access Formål
n8n.ditdomæne.com homeassistant:8123 Email-login påkrævet n8n dashboard / editor
n8n-hooks.ditdomæne.com [container]:5678 Ingen beskyttelse Webhooks fra eksterne systemer

Rute 2 — n8n Webhooks

FeltVærdi
Subdomainn8n-hooks
Domainditdomæne.com
Service TypeHTTP
Service URL[add-on-slug]:5678 eller 192.168.0.x:7123
No TLS Verify✓ Slået til
ℹ️
Service URL for webhooks — brug enten:
  • http://[add-on-slug-med-bindestreger]:5678 — container-til-container (bedst). Sluggen for f.eks. 6560bdea_hass-n8n bliver til 6560bdea-hass-n8n.
  • http://192.168.0.x:7123 — via host-IP og eksponeret port, hvis add-on'et viser port 7123 under Network-indstillinger.
⚠️ Brug ikke homeassistant:8123 for webhook-ruten. Port 8123 er HA's Ingress og returnerer nginx 404 for webhook-stier.
Sektion 4

Cloudflare Access opsætning

Gå til Zero Trust → Access → Applications.

🚫 Opret kun en Access-applikation for n8n.ditdomæne.com. Opret ingen applikation for n8n-hooks.ditdomæne.com — hvis der findes én, slet den.

Konfiguration af dashboard-applikationen

Sektion 5

n8n Add-on konfiguration

Gå til HA → Add-ons → n8n → Configuration. Miljøvariablerne skal sættes som følger:

timezone: Europe/Copenhagen
env_vars_list:
  - "N8N_WEBHOOK_URL: https://n8n-hooks.ditdomæne.com"
  - "WEBHOOK_URL: https://n8n-hooks.ditdomæne.com"
  - "EXTERNAL_URL: https://n8n.ditdomæne.com"
  - "NODE_FUNCTION_ALLOW_EXTERNAL: axios,moment,lodash,crypto-js"
cmd_line_args: ""
ℹ️

Begge webhook-variabler er nødvendige. Forskellige n8n-versioner bruger enten WEBHOOK_URL eller N8N_WEBHOOK_URL. Sæt begge for at dække alle versioner.

Vigtigt: Fjern N8N_BASIC_AUTH_ACTIVE: true hvis den ikke har tilhørende N8N_BASIC_AUTH_USER og N8N_BASIC_AUTH_PASSWORD — det crasher n8n ved opstart.

Genstart add-on'et efter ændringer. Verificer i loggen at variablerne er sat korrekt:

WEBHOOK_URL: https://n8n-hooks.ditdomæne.com   ← korrekt
N8N_EDITOR_BASE_URL: https://n8n.ditdomæne.com/api/hassio_ingress/[token]/  ← sat af add-on
Sektion 6

URL transformationsregel

På grund af HA Ingress-arkitekturen viser n8n's editor altid webhook-URL'er med Ingress-stien — selv efter korrekt konfiguration. Dette er en known limitation der ikke kan løses uden at modificere add-on'et.

Transformationsreglen er fast og enkel:

Editor viser https://n8n.ditdomæne.com/api/hassio_ingress/[lang token]/webhook-test/[uuid]
Brug denne https://n8n-hooks.ditdomæne.com/webhook-test/[uuid]

Reglen: erstat alt fra domænet til og med den skrå streg efter tokenet med https://n8n-hooks.ditdomæne.com/. UUID'et bevares uændret.

✅ UUID'et (f.eks. aeddd0f1-6851-4568-af1d-ae639f6eefb6) er permanent for det specifikke webhook-node og ændrer sig ikke ved genstarter eller sessionsfornyelse.

Test vs. produktion

URL-type Sti Aktiv hvornår
Test /webhook-test/[uuid] Kun mens du lytter aktivt i editoren
Produktion /webhook/[uuid] Altid, når workflowet er aktiveret (grøn toggle)

Brug URL Konverter-værktøjet til at omdan URL'er hurtigt.

Sektion 7

Test og verifikation

1
Verificer at hooks-domænet ikke er bag Access

Åbn https://n8n-hooks.ditdomæne.com i inkognito. Du skal se en n8n-fejlbesked (ikke en login-skærm).

2
Test et webhook-node

Opret et workflow med et Webhook-node i n8n. Klik "Listen for test event". Konstruér den korrekte URL med transformationsreglen og kald den:

Invoke-WebRequest -Uri "https://n8n-hooks.ditdomæne.com/webhook-test/[uuid]" -Method GET
3
Forventet svar fra n8n (bevis på succes) 
{"code":404,"message":"The requested webhook \"[uuid]\" is not registered."}

Enhver JSON-respons direkte fra n8n bekræfter at Access ikke blokerer. Hvis workflow-noden lytter aktivt, modtages requesten i n8n.

4
Aktivér til produktion

Slå workflowet til med den grønne toggle. Skift URL fra /webhook-test/ til /webhook/. Nu er webhooket permanent aktivt.

Sektion 8

Fejlfinding

Redirect til Cloudflare Access login-skærm

Kig på redirect-URL'ens hostname-parameter. Den afslører præcist hvilken Access-applikation der fanger requesten. Søg efter en wildcard-applikation (*.ditdomæne.com) under Zero Trust → Access → Applications.

404 fra nginx

Webhook-ruten peger på homeassistant:8123 (HA Ingress). Skift til container-hostname eller host-IP med den eksponerede port (typisk 7123 for racksync-add-on).

502 Bad Gateway

n8n-containeren er ikke nået eller porten er forkert. Verificer at add-on'et kører og at porten matcher (n8n's interne port er typisk 5678).

Hvid skærm i n8n editoren

Dashboard-ruten peger direkte på n8n-containerporten (5678) i stedet for HA Ingress (8123). WebSockets til push-notifikationer fungerer kun via Ingress. Skift dashboard-ruten til homeassistant:8123.

n8n crasher ved opstart

N8N_BASIC_AUTH_ACTIVE: true er sat uden tilhørende brugernavn og kodeord. Fjern variablen eller tilføj N8N_BASIC_AUTH_USER og N8N_BASIC_AUTH_PASSWORD.

EXTERNAL_URL er sat forkert

Skal pege på n8n's domæne — ikke HA's domæne (f.eks. ha.ditdomæne.com). Korrekt: https://n8n.ditdomæne.com.
